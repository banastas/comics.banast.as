# Full-site QA: September 7, 2026

Status: fixes implemented locally. Production has not been deployed from this QA task.

## Main finding

The live crawl checked all 1,292 sitemap URLs. **381 returned HTTP 404**: 152 series pages, 223 cover-artist pages, and 6 computed-tag pages. In-app navigation masked these failures because React could render those views without requesting their HTML. Refreshes, shared links, and search-engine visits failed.

The generator wrote percent-encoded directory names instead of the decoded asset names expected by Cloudflare. A first correction to decoded directories exposed another problem in Cloudflare's local runtime: directory redirects corrupted names containing question marks, hashes, and Unicode characters. The final generator writes decoded, flat HTML assets served at the existing extensionless public URLs. No record IDs, names, slugs, or collection data changed.

The full HTTP verification now passes for all 1,292 routes in Cloudflare's local Pages runtime, including the API Functions. This production issue remains live until these fixes are deployed.

## Findings resolved

| Priority | Finding | Resolution |
| --- | --- | --- |
| P1 | 381 public sitemap routes returned 404 on direct load. | Correct asset paths and avoid directory redirects. Add a complete HTTP crawl command and encoded-path regression tests. |
| P2 | Tag filters disappeared when changing view or sort; opening a comic lost search context. | Keep search and tag state in navigation URLs. Synchronize routing only on navigation/data load, rather than replaying it after every control change. |
| P2 | Shared search URLs could show unfiltered results while the asynchronous data chunk loaded. | Apply current filters when the data arrives; test shared filter/view/sort URLs. |
| P2 | Missing purchase prices were treated as free purchases in returns, series performance, and detail gain displays. | Calculate returns only from records with both prices known. Preserve total collection value, show coverage, and display missing costs as “Not recorded.” |
| P2 | Detail dashboards always reported zero variants. | Calculate variant totals from the displayed subset. The slabbed subset has 8 variants, rather than 0. |
| P2 | Detail breadcrumbs disappeared on narrow screens; pagination and statistics content overflowed. | Stack header controls, reduce nested mobile padding, make metrics responsive, constrain chart tooltips, and wrap pagination safely. |
| P2 | Detail list rows could overflow, and long lists rendered hundreds of records without pagination. | Responsive list rows and 48-record detail pages. Add navigation above and below lists; preserve the collection's initial view preference. |
| P2 | Mobile sort/view changes moved keyboard focus back to Close; dismissal left focus on the page body. | Stable close callback, focus trap, trigger restoration, and background scroll lock. |
| P2 | Malformed or nonexistent client routes could crash or leave stale content visible; legacy issue-only slugs could be confused with record IDs. | Recoverable, noindex not-found state; validated parameters; repaired legacy slug parsing. |
| P2 | Muted metadata and tinted dashboard labels had poor contrast. | Brighter muted text and darker metric-card backgrounds with readable labels. |
| P2 | A blocked storage read could crash startup; failed data loading looked like an empty editable collection. | Guard storage access and show an explicit reload state for load failures. |
| P3 | Recent-addition purchase dates used local time while other date displays used UTC. | Use the shared calendar-date formatter. |
| P3 | Navigating between related comics could retain stale cover-error state and scroll position. | Remount the detail view for the selected record. |
| P3 | Timeline values depended on hover. | Add an expandable monthly data table usable by touch and keyboard. |
| P3 | A recorded $0 current value could fall back to its purchase price. | Use nullish value fallbacks, with regression coverage. |
| P3 | Tablet-width search was too cramped; pagination required returning to the top. | Use compact header controls below 768px and add bottom pagination. |

## Verification

- Baseline `npm run check`: 34 tests passed, illustrating the missing behavioral and HTTP coverage.
- Updated `npm run check`: 66 tests across 21 files; data validation, all TypeScript targets, lint, build, sitemap, and static-page verification pass.
- `npm run verify:http -- http://127.0.0.1:5198`: all 1,292 routes, canonical metadata, unknown-route HTTP 404/noindex, all API record IDs, and API statistics pass in Cloudflare's local runtime.
- Live cover inventory: all 788 unique image URLs returned successful image responses to HEAD requests. This checks availability, not whether each image depicts the correct edition.
- Live API: 853 records and total current value of $6,730.31. Search and series filtering respond successfully.
- Live homepage security headers, robots, manifest, favicon, social image, and custom 404 checked successfully.
- Production dependency audit: zero reported vulnerabilities.
- Browser checks cover collection, statistics, boxes, raw/slabbed/variant subsets, series, artists, tags, comic details, search, grid/list switching, sorting, pagination, filter clearing, keyboard activation, dialog focus, and direct URLs.
- Responsive coverage includes 320px, 390px, 768px, and 1280px across nine page families, plus the 640px header breakpoint and a short landscape viewport.
- Direct browser loads verified the built routes containing `?`, `#`, Unicode, and an embedded slash in a series name.
- Canonical collection JSON and tracked sitemap are unchanged.

## Data and verification boundaries

280 records have no purchase price. The QA preserves those missing values rather than inventing costs. There are also 36 future-dated issues as of this audit; some covers intentionally show publisher placeholders. Neither availability checks nor screenshots establish whether those source records need editorial updates.

The browser pass used the Codex in-app browser at emulated viewport dimensions. Physical iOS/Android devices and separate Safari/Firefox engines were not tested. A production deployment and post-deployment crawl are still required before the live fixes can be declared complete.

## Repeat the HTTP check

```bash
npm run check
npx wrangler pages dev dist --port 5198 --compatibility-date 2026-07-17
# In a second terminal:
npm run verify:http -- http://127.0.0.1:5198
```

The explicit compatibility date works with the locally installed Cloudflare runtime. The same verification command accepts the live site origin after deployment. It intentionally checks every route, including names with punctuation and Unicode, rather than sampling only ASCII comic slugs.
